# weavedoc-gather

The data mine's intake channel — turn whatever is in `inbox/` into clean, classified, converted materials. Called repeatedly as new materials arrive; the mine grows with each call.

> **Language: read it first.** Read `language:` from `.weavedoc/config.yaml` and write **every** reply in that language. These skill files are English; your output is not.

> **Running weavedoc: pick the shell by platform.** Commands below are written `node .weavedoc/bin/weavedoc.mjs …` and read the same in every shell. **On Windows run them through PowerShell; everywhere else through bash** — Git Bash pays ~290ms per process to emulate Unix (measured: 373ms vs 80ms for one invocation), and a mine-wide command spends most of its time there. Never create a `.ps1` wrapper: PowerShell's execution policy applies to `.ps1` files and a downloaded one is blocked under `RemoteSigned`, while `node script.mjs` is not subject to it at all.

> **One writer per mine.** WeaveDoc is single-writer: one mutating session, and one mutating command, against a mine at a time (FORMATS.md). The CLI refuses a second mutating command; it cannot see YOU editing mine files directly, so never run this skill against a mine another session is writing to. A lost seal or verification row is evidence, not a cache — re-running the command is not the repair.

> **Surface, don't point.** A run that ends with anything waiting on the user — an unresolved conflict, an open question, a Human-queue entry, a fidelity violation, an open gap — must state each item **in the closing message itself**: what it is **in words** (the material's subject, the claim's content — an id is a machine handle and names nothing to a reader, who would have to open the file to learn what you meant; number the items in your message if the user will need to point at one) · the issue in one line (a conflict names both sides and their sources; a Human-queue entry keeps its ownership tag) · what the user must decide or supply. Every item gets its line — with many items, compress the detail, never the list. The file path comes *after* the substance, as the reference — never instead of it. "questions.md를 확인하세요" with the content only on disk is the handoff twin of the banned blanket "정확합니까?" (verify): no reviewable surface in the message, so the user must open files just to learn what is wrong. Ruled 2026-08-06 — real runs ended exactly that way ("파일을 안 열어봐도 어떤 부분이 문제인지 메시지로 명시"). Its mechanical source: `node .weavedoc/bin/weavedoc.mjs status --open` prints every open item across all five categories, one line each — take the list from that output and render it in the reply language, never re-compose it from memory (the census discipline, applied to the handoff).

> **Decisions: recommend + leave a way out.** When you ask the user to decide: **mark your recommended option `(추천)`** with a one-line why, and **always allow a free-form answer.** Don't force a closed pick.

> **Thin context.** Don't read all existing materials into context. Read only `catalog.md` (the index) for duplicate checking and id assignment. The truth is on disk; re-read when you need it.

> **Write-scope.** This skill writes to `materials/`, `catalog.md`, `questions.md` (an asked-but-unanswered item stays open there — the callout after the steps), and the root `.ignore` (creating or repairing the search shield per init §3, step 2). It does **not** touch `truths/`, `documents/`, or `project.md` (except to add a new role to `project.md.roles`).

> **The work's owner is the skill, not the session.** When a run spawns work another skill owns — a ruling mid-verify that needs a material (gather), a card correction (map), a document edit (write) — invoke that skill before doing the work; never imitate its output shape from memory. Imitation carries the visible conventions and drops the invisible duties. Measured (a real run): a verify walkthrough produced 8 materials and 23 cards inline with gather/map never loaded — all seven of the round's blocking findings clustered in that unloaded work, while the loaded skill's own procedure ran clean. Rule distance, not context volume, corrodes.

> **Grounding discipline.** (1) When the user questions where a recorded claim came from ("어디에 있어?", "그런 게 있어?"), **re-read the file before answering** — never answer from conversation memory — and show `source`/`location` + the verbatim line; withdraw anything you can't re-find. (2) Never attach a temporal/status modifier the material doesn't support (구버전·이전·최신·실제 적용·현행): if the label itself has no verbatim basis, use neutral wording ("m001에 기록된"). (3) Match confidence to evidence — a guess with no material basis is presented as a guess, never as "가능성이 높다"/"정확히".

## Authority — who decides, at this mine's level

Read `authority` from `.weavedoc/config.yaml`: `strict` | `standard` | `delegated`, and **absent means `standard`** (this axis is younger than every mine that exists, so absence is the normal state, not a gap). For work that belongs to a document, that document's `plan.md` frontmatter may override the mine's level; the override governs the document's own steps and leaves mine-side work at the mine's level, because nothing has ruled yet whether a strict document reaches back over the materials it draws on. **A decision the level's text does not name goes to the user.** Same fail-safe direction the Human queue's ownership tag takes, for the same reason: a decision the machine takes unasked is invisible, while one it surfaces costs a question. And the level says who decides, never what is true — the mirror rule, the quote seal, the intake declaration, conflict blocking and the fidelity gate hold identically at all three.

**This skill's row.** `strict` — the ratified summary stays verbatim-leaning: no form normalisation, the raw exchange attached beside it, `title` and `summary` wording approved by the user too, and no `> [machine-note]` written at all (a gap that needs saying goes to `questions.md`). One exception, and it is not a loophole: step 7's write-audit line is a record *of* an audit rather than machine framing, and its absence is what makes a conversion read as unaudited. `standard` — the ratified-summary flow exactly as §Conversation as a source states it: values are the user's, formatting and frame are the machine's inside the body-support rule. `delegated` — the machine drafts and registers, and the user reads it afterwards or approves in batches; the trigger does not relax (gather still moves only on an explicit request), and **until that batch approval lands the material is unratified**, so nothing in it may be read as a `stated` signature.

## Prerequisite gate
`.weavedoc/config.yaml` must exist. If not → tell the user to run `weavedoc init` first. **Stop.**

## Steps

1. **Duplicate check.** Before intake, read `catalog.md`. For each incoming item, check if a material with the same title or source_path already exists. If yes, warn the user and ask: update the existing one, or add as a new material? (Since intake **moves** inbox files out, a hit here means the same file was *dropped again later* — a deliberate re-drop, worth the question — not a leftover from the last run.)
2. **Intake.** For each item in `inbox/` (and any other sources the user points to): assign a stable id `m<NNN>` (next available), create `materials/<id>/`, and bring the original in as `source.<ext>`:
   - An **inbox item is MOVED** into the folder — not copied, not deleted. Nothing is lost (the byte-identical original now lives beside its `converted.md`, which is exactly the audit copy the retraction flow preserves), and the inbox stays a **queue**: what's in it is what's pending, an empty inbox means nothing awaits intake, and a processed file can never be re-detected as incoming. Ruled 2026-07-31 — before this, originals stayed behind and every later gather re-saw them as new arrivals.
   - A source **outside the project** (a path the user points to) is **COPIED** — never relocate files on the user's filesystem outside the mine.
   - **Ensure the search shield exists.** The moved original must land under the root `.ignore`'s shield (`inbox/` + `materials/*/source.*` — see init §3), so content searches from sessions that never invoke a skill cannot surface raw source text. If the mine predates the shield and has no `.ignore`, create it per init §3 before finishing the batch.
   - **Then DECLARE it — `node .weavedoc/bin/weavedoc.mjs intake <id> "<how it arrived>"`.** Run this as soon as the original is in place, before conversion: it hashes the `source.*` bytes at their most trustworthy moment and writes the row that says this material was *handed over* rather than *produced here*. The note is one line of plain text — where it came from and who gave it (`"inbox/contract.md — 사용자가 드롭"`, `"사용자가 세션에 붙여넣은 견적 메일"`). See **Declaration** below, which also covers the one case with no original.
3. **Convert.** Produce `materials/<id>/converted.md` from `.weavedoc/templates/material.md` — the source rendered as readable markdown. Preserve structure (headings, tables, lists). Do not alter or summarize away facts. **Do not ADD — converted.md is a mirror.** Three violations that actually happened, all banned: ① re-extracting values embedded in the body into a new summary table (the BPM/Key 표 incident), ② sort-order/superlative statements the source never makes ("세하가 최장신이다"), ③ cross-material consistency commentary ("이니셜 E와 정합"). Handling guidance genuinely needed but not in the source goes in one `> [note]` line (no new facts); machine framing in conversation materials goes in `> [machine-note]` (never promoted to a truth claim). Handle each format sensibly (pdf, docx, xlsx, image → text/description, etc.).

   **A measured figure carries its measurement.** When a `> [note]`/`> [machine-note]` line presents a number as measured (실측 — a count, a ratio, a percentage), it writes the measurement date and the exact command that produced it beside the number. A figure you cannot re-run in the same breath is not written: re-measure it or drop it. Measured (a real run): a note asserted `무관한 카드 21건(실측)` and no scope reproduces 21 as cards — `pull` returns 5, a card-grep 15, and 21 counts *files*, four of them ledgers — while a sibling material wrote "8종" and then listed nine. These lines are exempt from the mirror checks by design, so nothing downstream ever re-counts them; a number with no command is a memory wearing a measurement's clothes, and the mine cites it later as evidence.
4. **Classify (frontmatter).** Fill per `.weavedoc/FORMATS.md`: `title`, `origin` (`file` for inbox items, `conversation` for a declared session — see below; `user-answer`/`prior-doc` come from the ask and series loops; **`research` when *you* fetched it** — see below), `role` (one of `project.md` `roles`), `topics` (free tags), `format`, `source_path` (the **pre-move** path for inbox items — record it before step 2 moves the file; non-file origins take their non-path handle per FORMATS), `added` (intake date), `status: converted`, `summary` (2–3 lines), **`dated`** when the source states its own date (signing/meeting/revision date — the source's own claim about when it was written, context the user may lean on when ruling a conflict; omit rather than guess, and never copy `added` into it — no one, machine or AI, resolves a conflict by date), and `stage` (`plan` | `applied`) when the source is clearly a plan/proposal vs a record of what was actually applied — truths from `plan` materials carry an "실행 확인 안 됨" caveat, so this one field prevents plan content masquerading as usage history.
   - **`corrects`** — when the material's purpose is to displace part of an earlier one (a correction the user gave after seeing a truth was wrong), list what it displaces: `corrects: [m011 §4]`. `map` reads this to know exactly what to re-ground instead of inferring it, and it is what tells a body-only reader that this is a correction and not a new setting.
5. **Roles — silent metadata, no interview.** Assign each material a `role` yourself (a short descriptive label in the project language, e.g. 기획/참고/기준). If the role isn't in `project.md` `roles` yet, append it there silently. **Do NOT ask the user to design or confirm a role vocabulary** — a role earns user attention only when it's consumed: it frames a conflict question ("계약서 vs 회의록") when map lays a disagreement before the user. The user can edit roles in `project.md` anytime; just don't block intake on taxonomy questions.
6. **Index.** Regenerate `catalog.md` from all material frontmatter (actually regenerate — don't append rows and call it regeneration).
7. **Self-audit in BOTH directions, then report.** The cold `verify` lane re-runs the three lenses below as its M1–M3 (its material axis carries a fourth, M4 Reachability, for `origin: research` only — that one is verify's own); **all three are this step's job first.** Verify exists for what this step missed — not as the place the rules live. Ruled 2026-08-16 after a real run: the write side carried only one of the three, so the other two were paid for later with cold reviewers, per material, forever.

   Walk each one and **write the result down before you report** — an unshown check is not done:

   - **Nothing added (converted → source — verify's M3).** Walk every heading / table / bracketed annotation in converted.md and point to its source.md location. **List everything you cannot point to; the list must be empty** (delete the item or demote it to a `> [note]`). A converted.md with more sections or tables than its source is an automatic flag.
   - **Nothing lost (source → converted — verify's M1).** The other direction, and the one that used to be missing: walk every section, paragraph, table and data point of the ORIGINAL and name where each landed. **Missing content is a defect, not a summary.** This is the direction "more sections than its source" cannot see — a conversion that drops a table reads as clean under a one-way sweep.
   - **Values match exactly (verify's M2).** Cross-check ALL structured data against the original — table cells, enumerated items, numbers, dates, amounts, names, labels, and any string you present as a quote. Not a spot check: a misread cell is indistinguishable from a correct one until someone compares it. Spacing inside a quoted string is part of the value (a real run preserved `이야기 속` vs `이야기속` per position, and that difference was the evidence that no normalization had occurred).

   **The audit leaves a line in the material.** Write the result into converted.md itself, as its final `> [machine-note]`: `> [machine-note] 쓰기 대조 <date> — 본문 N줄 대조 N/N · note 사실 진술 N건 원본 확인`. A `user-answer`/`conversation` conversion without this line reads as **unaudited**, and the cold lane's M1 starts by reproducing it. The line is a **claim, not evidence** — it defends forgetting, not forgery, and the cold lane re-checks it (the intake ledger states the same limit about itself). Its own figures need no command: the audit *is* the procedure, and M1's re-walk is the re-run. Measured (a real run): a session skipped this audit entirely, nothing recorded the skip, and all seven of that round's blocking findings sat in the unaudited work.

   In the report, name any `> [note]`/`> [machine-note]` lines you added. (The BPM-table incident was caught only because the user happened to read the completion report — this step removes the luck.) If a mirror violation is found later, it is **not a user choice**: remove it immediately, report "제거했습니다 + 이유", and re-audit the whole batch — the same slip rarely happens once (5 sibling violations survived unnoticed in a real run because the caught one was treated as isolated).

> **Asked-but-unanswered stays open.** If something was requested from the user and they didn't answer (e.g. a value requested right before "gather 하자"), a material-side "미제공" note is not enough — keep it as an `open` entry in `questions.md`. Reporting "열린 갭 0" while an asked item is unanswered is false.

## Declaration — every material says how it arrived

**`node .weavedoc/bin/weavedoc.mjs intake [--no-source] <id> "<note>"`, once per material, in step 2.** It appends a row to `materials/intake-ledger.tsv` carrying a digest over the folder's `source.*` bytes. `validate` warns `MAT-UNDECLARED` for a material with no row; `scope` and `census` count declared, no-source, legacy-unbound and undeclared apart.

**Why this exists, stated plainly: you write the material AND the cards that cite it.** So a material you invented is structurally perfect — the quotes match, coverage closes, the seals pass, `validate` is green. Nothing downstream can catch it, because everything downstream checks the cards *against the material*. The declaration is the one place the question "did this come from outside?" is asked at all.

**It cannot stop you from inventing a `source.md` and declaring it, and it is not meant to.** What it does is remove the silent path: a material that just appears is now named. Which means the rule that already governs this decision is the one that matters, and it is above and below in this file — **a direction about the document is not a material.** A real run (2026-08-14) took the owner's instruction *"delete the Knock:One personal narrative"* — a statement about the *mine*, not about the world — and began registering it as correction material `m033` with `corrects: [m003 §6]`. What stopped it was one incidental judgment ("there's no original to quote"); a plausible invented sentence would have passed `validate` intact. Before you run `intake`, say what the original is and where it is. If the answer is "the user told me to change the mine", it is not a material — route it to the skill that owns the change (map for a truth correction, plan for a document direction).

**`--no-source` is the one exception, and it is a ruling, not a fallback.** A material with genuinely no original — a value the user stated with nothing to compare against — takes `intake --no-source <id> "<the ruling, in the user's words>"`. It binds no bytes, so no later check can compare that material against anything; it is counted apart everywhere. Use it when the user has ruled it, and quote them. **Never reach for it because the source file is inconvenient to produce** — that is the failure this whole ledger exists to make visible, taken one step earlier.

**Re-declare when an original legitimately changes.** `scope` reports `stale (source)` when a declared material's source bytes no longer match the row. Re-run `intake` with a note saying what changed. (A *correction* to the content is different: it enters as a new material with `corrects:`, never as an edit to the old original.)

**`stale (copy)` is the other one, and it is the one that went wrong.** The row also binds `converted.md`, so `scope` reports when the mine's *copy* has been edited since it was declared. Two things can produce that line and only one of them is legitimate:

| what moved the bytes | legitimate? | what to do |
|---|---|---|
| a **conversion fix** — the copy was wrong about the original, now it is right | yes, expected | re-run `intake <id>` with a note naming the fix |
| a **decision about the mine** written into the copy | **never** | revert the copy; route the decision (below) |

The material is the mine's record of *what a document said*. That does not change when the project changes — the document still said it. So an owner saying "drop this from the project" is answered on the truth axis, not here: **retract the truths** (`map`), or bring the correction in **as a material** with `corrects:`. Editing the copy to say what the original did not is falsifying the record, whatever the intention — and it does not even achieve the goal, because the truths that quote the deleted text are still there.

This is not hypothetical and it is not a rule invented for this file. A real run (2026-08-14) was told to drop a group's worldbuilding from the project and carried it out by deleting a column out of `materials/m003/converted.md`. That material had never been verified, so it bound no bytes and nothing reported the edit; every later reviewer met a mismatch it could not explain, and the next move considered was to invent a correction material to justify it. The binding above is what makes that first edit visible on the day it happens. **If a material predates the ledger and binds nothing, `scope` says so** — `scope` and `census` name the count, and `intake --anchor-existing "<what you are vouching for>"` binds them in place. Check the tree is the one you mean first; an anchor adopts what it finds, and anchoring is not verification.

## The machine fetched it — `origin: research`

When a value comes from **you** going and getting it (a web search, a fetched table, an external dataset), it is not a user answer and must not be filed as one. There is no human between the world and the record, so the material carries the whole burden of being re-checkable.

- `origin: research`, plus **`url`** and **`retrieved_at`** — `validate` blocks without them.
- **`source.md` holds the values as fetched** — raw units, raw timezone, before any conversion — with every source URL. If you converted (UT → KST, USD → KRW), *both* forms go in: the fetched one is the evidence, the converted one is your work. A reviewer who can't see the raw value can only re-search, not re-check.
- Cross-check a second source when the value is load-bearing, and record both.
- The question that prompted the search, and the user's acceptance of the result, belong in `source.md` too — the value is `adopted`, not `stated`, and that only shows if the exchange is there.
- **Declare it, and never as `--no-source`.** This is the origin with no human between the world and the record, so it is the one where an invented `source.md` is hardest to notice — the digest over the fetched bytes plus the `url`/`retrieved_at` pair are all a cold reviewer has. `intake <id> "<the query, and the source fetched>"`.

Verified at `full`, always. A real run searched solstice dates, filed them `user-answer` because nothing else fit, and the project's entire age table came to rest on figures no later reviewer could re-reach.

## Conversation as a source — the ratified summary IS the original

When the user declares this session (or a stretch of it) as a source — "이 대화를 자료로", "이걸 토대로 gather 해줘" — treat it as intake, not a file. And that declaration is the ONLY trigger: **never register the user's utterances as they arrive.** Conversation accumulates; gather moves on the explicit request alone — that the user just said something worth keeping is not the request. Ruled 2026-08-28: "내가 뭔가를 말할때마다 그걸 새로운 원본삼아 gather 하려고 하지마."

The same ruling replaced the raw-exchange snapshot this section used to prescribe, for a measured reason: utterances in conversation are structurally deictic (`응` · `맞아` · `넷 다 그래` — every antecedent on the machine's side), so a raw original forces the machine turns to be carried along as `> [machine-note]` lines, and that layer is exempt from the mirror checks by design. In a real mine (2026-08-28) it grew to 7–26× the body across four materials, and ALL blocking findings of a 4-round cold cycle sat in machine-authored prose — the note layer and the frame (title · summary · 소제목) — while the body itself never failed once. A ratified summary has no antecedents to carry, so the layer loses its reason to exist.

1. **Draft the summary.** Distill the FINAL CONCLUSIONS only — not the exchange, not the dead ends, not the machine's questions. Self-contained declarative sentences: nothing that needs a machine turn to mean anything. What the conversation never settled is not a conclusion — it stays open in `questions.md` (the callout above), never in the draft as fact. A **direction about the document** ("2페이지로", "리스크 앵글로") is still not a material — pass it to `plan`; a direction about the mine routes per Declaration above. Any value that originated as a machine proposal is **marked in the draft** — `[기계 제안값]` beside the value — so the user signs it knowingly.
2. **Present it in chat and ask: "이대로 원본으로 올려도 됩니까?"** The user edits or approves. Create `materials/<id>/` and write the approved text to `source.md` byte-for-byte — the user's words now, by ratification (a marked value the user rewrote is theirs: the replacement enters unmarked). Then **declare it** — `intake <id> "<the approving utterance, quoted>"`: the ratified `source.md` IS the original, an ordinary digest-bound declaration and never `--no-source`, and the intake note is where the approving utterance becomes a record instead of a memory.
3. **converted.md is its mirror.** A self-contained original leaves nothing to carry — no settling exchanges, no antecedent notes. A `> [machine-note]` in a ratified-summary material needs a reason to exist at all; the one line it still ends with is step 7's write-audit.
4. Classify, roles, index, and self-audit as in steps 4–7 above.

**Provenance**: ratification makes every sentence `stated`. A value the draft marked as machine-proposed and the user approved unchanged is `adopted` — **the mark in the ratified original IS the visible adoption exchange** (`map` reads it off the body; FORMATS defines it under `provenance`). The mark is annotation, never claim content.

**Not retroactive.** Materials registered under the raw-exchange shape stay exactly as they are, read under the rules that made them — for a raw original, carrying the machine turns was and remains the right duty. This section governs new registrations only.

**An ask-loop batch (`origin: user-answer`) still snapshots the exchange.** It is a different shape — the question is the machine's, the answer arrives leaning on it, and registration is part of a loop the user is already driving — so its `source.md` remains the raw exchange, and three hard rules govern the excerpt:
   - **Preserve the settling exchange.** When a fact was settled by the user confirming or choosing a machine proposal, keep the proposal AND the confirming utterance together, attributed: `제안(기계): 라온고·윤슬고·서연고 / 채택(사용자): "라온이 좋아보여"`. Stripping the machine side turns source.md into a user-monologue that can't ground what converted.md asserts — and it hides which values were machine-originated (those become `provenance: adopted` truths at map).
   - **No question→declarative promotion.** A user utterance that is question-form ("~하면 어때?") may appear as a settled declarative in converted.md **only if** the exchange that settled it is preserved in source.md. If nothing settled it, it goes to `questions.md`, not into the material as fact. (A real run hardened "현관 열면 바로 사무실…어때?" into "대표실이 따로 있는 구조가 아니다" — a machine-made negative proposition the user later corrected.)
   - **The settling exchange reaches converted.md too.** When a user answer *leans on* a machine turn — accepting a proposal, answering a question, pointing with a demonstrative ("그 서사", "넷 다 그래") — that machine turn is carried into converted.md as a `> [machine-note]` line labeled as machine speech, never woven into the body. Keeping it in source.md alone is not enough: the search shield makes that file unreachable to every protocol-following reader, so a value whose only antecedent lives in a dropped machine turn is, to the mine's consumers, grounded nowhere. Measured (a real run): a converted.md dropped all five machine turns while its own `summary` asserted "2집 유나" — the value happened to be right, and there was no longer anywhere a reader could go to see why.

   Machine framing that must be recorded (an anchor like 세는나이 기준, a normalization) is a `> [machine-note]` line — **never woven into the user's words** in source.md or converted.md; and when the user's answer leans on that framing, carrying it into converted.md is required, not optional (the third rule above). Declare the batch like any other material — `intake <id> "<the question batch it answers>"`: the snapshot IS the original, ordinary and digest-bound, never `--no-source`.

## Retracting a material

When the user withdraws a source ("m005 빼줘", "이 자료는 잘못됐어") — first check which case it is. **Replacement is the norm; retraction is rare.** If a corrected version exists (or the user can supply one), use the replacement flow: gather the correction (with `corrects:`), let map re-ground the affected cards in place — the truth changes because its grounding changed. Retract only when the material should stop grounding anything, with nothing in its place.

1. **Show the blast radius first.** Run `node .weavedoc/bin/weavedoc.mjs impact <id>` and show what falls: which materials already **correct** it, which truths were extracted from it, which documents cite them. Read the corrections before proposing anything — a material six later ones already amend is usually a replacement case, not a retraction. Confirm with the user before touching anything.
2. **Mark, never delete.** Set the material's frontmatter `status: retracted`. The folder, `source.*`, and `converted.md` all stay — the mine keeps its audit trail; a retracted material grounds nothing but still shows what was once declared.
3. **Regenerate `catalog.md`** (the status column shows it).
4. **Route to map for propagation** — truths are map's write-scope, not gather's: every truth grounded on the retracted material is re-grounded on a live one or deleted (map's correction table, "source retracted" row), citing documents → `stale`. `weavedoc validate` enforces it mechanically — a canonical card still grounded on a retracted material is `TRUTH-SOURCE-DANGLING`, so nothing rides on memory.
